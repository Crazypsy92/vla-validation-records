状态为 **第一阶段待验收**。本轮修复、无模型测试与真实窗口回放均已执行。Seed 203 正式补测和完整模型内存预算测量留在第二阶段。

## 工程位置与版本

Codex 桌面端访问本机 Windows 与 WSL2。代码位于本机 VLA 工程，入口依次为桌面快捷方式、`workbench/start.sh`、`workbench/app.py`。实际工程目录没有 Git 元数据。独立本地源码快照 `task020-r1` 保留修改前基线 `545411c` 和修改后提交 `ad43ca9`。源码差异、修改文件与提交可在本地 `results/task020/r1/source.diff` 和版本 JSON 检查。

## 代码改动

- Task 5 运行和回放会更新左侧书本指令、Episode、Seed、Step、双视角和当前 8D 状态。从 Task 5 返回离线时恢复原基准样本。历史回放的 Seed 与 `Next Run Seed` 分开。未封装完的旧中断 MP4 可进入 `INCOMPLETE` 回放，只有同一个步号留存的原始双图可以显示。
- 离线 Worker 按需启动。若有离线请求或加载的离线模型，先结束该操作并卸载。启动书本试点前会让空闲的离线 Worker 退出。切换到书本标签会清理上一回放的帧缓存。
- GUI 每秒与阶段切换时分别记录系统可用内存、Swap 和进程 RSS/PSS。Worker 在加载前后、复位并开启录像后、每次前向前后、动作块和视频写入后及环境关闭后记录采样。数据按 JSONL 追加。
- 保护条件为可用内存低于 512 MiB，或可用内存低于 1024 MiB 且启用的 Swap 剩余低于 128 MiB。触发后发出 `RESOURCE_PRESSURE`，Worker 在安全边界停止并保存。已在执行的单次模型前向须返回后才有机会协作停止，单次分配过快或内核先杀进程仍可能中断 MP4。GUI 存活时会记录异常退出及已知进度。

## 资源证据

Windows 总内存 16092 MiB，采样时可用 2805 MiB，未发现 `.wslconfig`。WSL 总内存 7798 MiB，Swap 总量 2048 MiB。历史内核日志确认过 WSL 全局 OOM，前两次完整回合的 Worker 峰值约 6.7 GiB RSS。现有证据尚无法判断是否存在模型内存泄漏。

| 本轮样本 | WSL 可用 MiB | Swap 可用 MiB | 测试进程 RSS/PSS MiB |
| --- | ---: | ---: | ---: |
| 启动界面与回放前 | 6308 | 936 | 682 / 676 |
| 停止子进程、关闭界面后 | 5990 | 937 | 971 / 965 |
| 注入的模拟压力 | 350 | 64 | 测试覆盖值 |

前后两条是不同生命周期阶段的系统快照，测试进程还持有 GUI/解码相关库，数差不能直接作为泄漏量。测试子进程复核为已回收。模拟压力不是宿主机实测。第二阶段需要单独测量真实加载、前向和录像峰值。当前 7.62 GiB WSL 上限相对于已知 6.7 GiB RSS 峰值的余量较窄。任何宿主配置调整单独审批。
